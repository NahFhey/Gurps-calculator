# SPEC: JS→TS Conversion — gathering.js and alchemy.js (Phase 15e)

## Background

React 18 + TypeScript (`strict: true`) GURPS campaign manager. Two legacy
JavaScript utility modules remain in `src/utils/`; both are load-bearing and
have hand-written `.d.ts` declaration files that consumers currently rely on:

- `src/utils/gathering.js` (823 lines) + `src/utils/gathering.d.ts` — consumed
  by GatheringTab, the downtime Fishing/Foraging/Mining activity + resolution
  views, and others.
- `src/utils/alchemy.js` (1,366 lines) + `src/utils/alchemy.d.ts` — the alchemy
  math engine (formula stats, roles, hazards, tiers), consumed by the alchemy
  views (BatchesView, ConcentrationRefinementView, TallyWorksheetView,
  FormulasView) and `campaignReducer.ts`.

Each also has characterization tests in BOTH `.js` and `.ts` form under
`src/utils/__tests__/` (`gathering.test.js`, `gathering.test.ts`,
`alchemy.test.js`, `alchemy.test.ts`). These pin current behavior.

## Deliverable

Convert both modules to TypeScript, one commit-worth of change per module
(but do NOT run git):

1. `gathering.js` → `gathering.ts`; `alchemy.js` → `alchemy.ts`. Delete the
   corresponding `.d.ts` file in the same change — its declarations become the
   real exported types of the `.ts` module. Reconcile: where the `.d.ts` and the
   actual JS behavior disagree, the JS RUNTIME BEHAVIOR wins and the type gets
   corrected (note each such case in your summary).
2. **Behavior must be byte-for-byte identical.** This is a typing exercise, not
   a refactor: no logic changes, no renamed exports, no reordered defaults, no
   "improvements". Consumers must compile without ANY edits — if a consumer
   fails to compile against your types, your types are wrong (or the .d.ts was
   — reconcile per rule 1), not the consumer. Exception: an import line in a
   consumer may be touched ONLY if it references the `.js` extension explicitly.
3. **Typing rules (hard constraints):**
   - NO `as any`, no `@ts-ignore`, no `@ts-expect-error`.
   - Type the module boundaries precisely (exported function signatures,
     parameter/return types) using existing domain types from
     `src/types/campaign.ts` (`AlchemyReagent`, `AlchemyFormula`,
     `AlchemyBatch`, `MaterialType`, ...) and `src/types/` generally — do NOT
     invent parallel shapes for things that already have a type.
   - For genuinely dynamic internals, prefer precise unions / generics /
     `unknown` with narrowing over loose `Record<string, any>`. A small number
     of internal `Record<string, unknown>` is acceptable where the data is
     genuinely open; `any` is not.
   - `RollableTable` already exists in `src/types/gathering.d.ts` (created in
     Phase 10a to bridge these utils) — check for it and reuse/merge rather
     than duplicating. If a type file like `src/types/gathering.d.ts` becomes
     redundant after conversion, fold it in and delete it, keeping consumers
     compiling unchanged.
4. Keep the module-level JSDoc comments that document GURPS rules/formulas —
   they are domain knowledge, not noise. Drop only comments made redundant by
   types (e.g. `@param {number}` annotations).

## Constraints

- `strict: true` clean: `npx tsc --noEmit` across the whole repo.
- Files you may edit/create/delete: `src/utils/gathering.{js,ts,d.ts}`,
  `src/utils/alchemy.{js,ts,d.ts}`, `src/types/gathering.d.ts` (fold-in only),
  and the four characterization test files (ONLY to fix imports/types, never to
  weaken an assertion — if a test fails against your conversion, the conversion
  is wrong). Consumer files only under rule 2's exception.
- No new dependencies. Do not commit to git.

## Definition of done — self-verify before finishing

1. All four characterization suites pass unchanged in what they assert:
   `npx vitest run src/utils/__tests__/gathering.test.js src/utils/__tests__/gathering.test.ts src/utils/__tests__/alchemy.test.js src/utils/__tests__/alchemy.test.ts`
2. Consumers compile and their suites pass:
   `npx vitest run src/components/alchemy/ src/components/downtime/ src/components/manager/ src/state/`
3. `npx tsc --noEmit` clean; `grep -n "as any" src/utils/gathering.ts src/utils/alchemy.ts` returns nothing.
4. Final summary: one paragraph per module — the trickiest signatures, every
   .d.ts-vs-runtime disagreement you reconciled (and which side won), and any
   consumer import lines touched under rule 2's exception.
