## Background (why)

The party's social standing lives in the GM's head: no reputation, faction, or
NPC entities exist, and `gcsData.reactions` is import-only decoration. This
lane adds a campaign-level **relationship ledger** (`entities.contacts`) and a
`'social'` downtime activity whose influence rolls shift ledger entries'
reaction modifiers.

Codebase rules: strict TS (`npx tsc --noEmit` clean), **no `as any` anywhere
incl. tests, no ts-suppressions**, Immer reducers, `useCampaignStore()` /
`useDowntimeContext()`, logic in utils/reducers not components, `import type`,
dark-Tailwind + `data-testid` per the downtime views.

## Deliverable 1: contact ledger state

- `src/types/campaign.ts`:
  ```ts
  export type ContactKind = 'person' | 'faction' | 'settlement';
  export interface ContactShift {
    id: Id;
    dayKey: number;
    delta: number;            // signed change applied (post-clamp)
    newModifier: number;
    cause: string;            // e.g. "Carousing success by Rina" or "GM adjustment"
    timestamp: number;
  }
  export interface ContactEntry {
    id: Id;
    name: string;
    kind: ContactKind;
    modifier: number;         // reaction modifier, clamped to [-4, 4]
    notes?: string;
    history: ContactShift[];
    createdAt: number;
    updatedAt: number;
  }
  ```
  Entities shape: `contacts?: Record<Id, ContactEntry>`.
- Campaign reducer actions + store creators (follow studyProjects pattern):
  - `upsertContact(entry: ContactEntry)`
  - `removeContact(id: Id)`
  - `shiftContactModifier(id: Id, delta: number, cause: string, dayKey: number)`
    — reducer clamps the resulting modifier to ±4, records the actually-applied
    delta in a `ContactShift` appended to `history`, stamps `updatedAt`.
    Delta 0 still appends a history line (a failed attempt is table history)
    with `delta: 0`.
- Selectors: `selectContacts` (`?? {}`), `selectContactByName(state, name)` —
  case-insensitive trimmed name match, used by find-or-create and the trading
  badge.

## Deliverable 2: influence engine — `src/utils/social.ts` (pure)

```ts
export interface InfluenceSkillDef {
  key: string;               // lowercase activity key, e.g. 'diplomacy'
  gcsName: string;           // 'Diplomacy'
  defaultAttribute: 'IQ' | 'Will' | 'HT';
  defaultPenalty: number;    // RAW: Diplomacy -6, FastTalk -5, SavoirFaire -4, Streetwise -5, Intimidation -5 (Will), Carousing -4 (HT)
}
export const INFLUENCE_SKILLS: InfluenceSkillDef[]; // the six above

/** Mirror getMerchantSkill (src/utils/trading.ts): merged skills via
 *  getCharacterSkills, try def.key then def.gcsName; absent/0 → attribute
 *  value (gcsData.attributes / secondaryAttributes for Will; fallback 10)
 *  + defaultPenalty, isDefault: true. */
export function getInfluenceSkill(character: CharacterLike, def: InfluenceSkillDef): { level: number; isDefault: boolean };

export interface SocialAttemptResult {
  roll: RollVsTargetResult;      // 3d6 vs effectiveTarget
  effectiveTarget: number;       // skill level + contact's current modifier
  critSuccess: boolean;
  critFailure: boolean;
  delta: number;                 // +2 crit / +1 success / 0 fail / -1 critfail (pre-clamp)
}
export function resolveSocialAttempt(skillLevel: number, currentModifier: number): SocialAttemptResult;
```

Use `rollVsTarget` from `src/utils/dice.ts` and the critical helpers from
`src/utils/gathering.ts` (the same ones `resolveHaggle` imports).

## Deliverable 4: UI — `src/components/downtime/views/`

### `SocialActivity.tsx`
Study-lane structure: a **Ledger** section above the task lists, then
pending/completed task cards. Parent owns all dispatches.
- **Ledger cards** (`data-testid="contact-card"`): name, kind tag, modifier
  badge (color: green positive, gray 0, red negative, always signed), notes
  preview, expandable day-stamped history list, edit (name/kind/notes +
  direct modifier set → `shiftContactModifier` with cause "GM adjustment"),
  delete with confirm. **"Add contact" button** with inline form.
- Task create: target picker = existing contacts + "New contact…" (name +
  kind; created via `upsertContact` at modifier 0, history empty) — stamp
  `contactId`/`contactName` into `SocialData`.
- Resolution (in `handleFinalize` after the panel reports):
  `shiftContactModifier(contactId, delta, cause, currentDayKey)` →
  `resolve(taskId, results)` with a message carrying roll numbers and the new
  modifier → `addLogEntry(socialLog.attemptResolved(...))` with meta
  `{ characterIds: [leaderId], taskId, quantity: delta }`.

### `SocialTaskForm.tsx`
Leader select; contact picker (with New contact… path); approach select over
`INFLUENCE_SKILLS` showing the leader's level per skill via
`getInfluenceSkill` — "Diplomacy-14" or "Carousing (default HT−4 = 6)";
preview line "Roll vs 14 + current standing (−2) = 12". No batch mode.
Validate via `validateTaskCreation`.

### `SocialTaskCard.tsx`
Contact name + kind, leader + chosen skill (+default tag), status badge;
pending → Resolve (`data-testid="resolve-button"`) / Cancel; resolved →
results message.

### `SocialResolutionPanel.tsx`
Shows contact (name, current modifier), leader + skill level breakdown,
effective target; "Roll" button (`data-testid="roll-social-button"`) → one
`resolveSocialAttempt`, displays dice/target/outcome/delta and the would-be
new modifier (clamped, "already at the cap" note when clamp bites);
Apply (`data-testid="apply-social-button"`, enabled after rolling) →
`onFinalize(results, attempt)`; Cancel.

### Trading cross-surface (one small edit)
In `TradingTaskForm.tsx`: when the merchant-name field case-insensitively
matches a `ContactEntry` name, show a small standing badge next to the field
("Dockworkers' Guild: +2", `data-testid="merchant-standing-badge"`).
Display-only — do not alter any trading math.

Export the new components from `views/index.ts`.
