## Background (why)

Downtime has no path from time to advancement. This lane adds a `'study'`
activity: slot-bounded study tasks credit hours into persistent per-
character+skill **StudyProject** entities (the Craft/AlchemyBatch precedent:
tasks stay single-slot, accumulation lives in `state.entities`); at a
configurable threshold the GM ratifies a skill point with one click, which
programmatically runs the character sheet's Record Advancement mechanics.

Codebase rules: strict TS (`npx tsc --noEmit` clean), **no `as any` anywhere
incl. tests, no ts-suppressions**, Immer reducers, `useCampaignStore()` /
`useDowntimeContext()`, logic in utils/reducers not components, `import type`,
dark-Tailwind + `data-testid` per the downtime views.

## Deliverable 1: types + config

- `src/types/campaign.ts`:
  ```ts
  export interface StudyProject {
    id: Id;
    characterId: Id;
    skillName: string;
    specialization?: string;
    attribute: SkillAttribute;        // import type from characterSheet
    difficulty: SkillDifficulty;
    accumulatedHours: number;
    pointsAwarded: number;
    createdAt: number;
    updatedAt: number;
  }
  export interface StudyConfig { hoursPerPoint: number }
  ```
  Entities shape: `studyProjects?: Record<Id, StudyProject>`,
  `studyConfig?: StudyConfig`.
- `src/constants/index.ts`: `DEFAULT_STUDY_CONFIG: StudyConfig =
  { hoursPerPoint: 200 }` and `STUDY_HOURS_PER_SLOT = 4`.
- Campaign reducer actions + store creators (follow the trading lane's
  `setCurrencyConfig`/price-book pattern):
  - `setStudyConfig(config: StudyConfig)`
  - `upsertStudyProject(project: StudyProject)`
  - `removeStudyProject(id: Id)`
  - `creditStudyHours(projectId: Id, hours: number)` (adds, stamps updatedAt)
  - `awardStudyPoint(projectId: Id)` — reducer subtracts
    `studyConfig.hoursPerPoint` (fallback default) from `accumulatedHours`
    (floor 0), increments `pointsAwarded`, stamps `updatedAt`. Guard: no-op if
    `accumulatedHours < hoursPerPoint`. **The character-sheet mutation happens
    in the same dispatch site via `updateCharacter` (Deliverable 3), not in
    this reducer case.**
- Read-fallback selectors/helpers: `selectStudyConfig` (`?? DEFAULT_STUDY_CONFIG`),
  `selectStudyProjects` (`?? {}`), `selectStudyProjectsForCharacter`.

## Deliverable 2: study engine — `src/utils/study.ts` (pure)

```ts
/** 4 full-rate hours when a teacher helper or good materials are present, else 2. */
export function computeStudyHours(hasTeacher: boolean, goodMaterials: boolean): number;

/** Find a character's current entry for a studied skill (match name +
 *  optional specialization, case-insensitive trim) in gcsData.skills. */
export function findStudiedSkill(character: CharacterLike, skillName: string, specialization?: string): Skill | undefined;

/** Teacher eligibility: teacher's merged skill level (getCharacterSkills, try
 *  "Name (Spec)" then "Name") must exceed the student's current level for that
 *  skill (student without the skill: any teacher level > 0 qualifies). */
export function isEligibleTeacher(teacher: CharacterLike, student: CharacterLike, skillName: string, specialization?: string): boolean;

export interface StudyAwardComputation {
  isNewSkill: boolean;
  previousPoints: number; newPoints: number;      // +1
  previousLevel: number; newLevel: number;        // via calculateSkillLevel
  previousRelativeLevel: number; newRelativeLevel: number;
  updatedSkills: Skill[];                          // full replacement array for gcsData.skills
  historyEntry: SkillAdvancementEntry;             // sessionLabel "Study — Day N"
}
/** Compute the full award: for an existing skill add 1 point and recompute
 *  level/relativeLevel (calculateSkillLevel / calculateRelativeLevel from
 *  characterSheet.ts — attribute value from gcsData.attributes, Will/Per from
 *  secondaryAttributes); for a new skill create the Skill entry (1 point,
 *  computed level, generated id). Mirrors SkillHistorySection.handleRecordAdvancement
 *  exactly — read it first. dayKey feeds the session label. */
export function computeStudyAward(character: CharacterWithGCS, project: StudyProject, dayKey: number): StudyAwardComputation;
```

Use existing `calculateSkillLevel`/`calculateRelativeLevel` — do not reimplement
the B170 ladder. `SkillAdvancementEntry.id`: use a random suffix, not bare
`Date.now()` (the existing `adv-${Date.now()}` pattern is collision-prone; note
this divergence in your summary).

## Deliverable 4: UI — `src/components/downtime/views/`

### `StudyActivity.tsx`
Rest-lane structure plus a **Projects** section above the task lists:
- **Projects**: card per `StudyProject` of any party character — character +
  skill name, progress bar `accumulatedHours / hoursPerPoint`, `pointsAwarded`
  tally, **"Ready to award" badge** when over threshold with an **Award point**
  button (`data-testid="award-point-button"`), and an abandon (delete) button
  with a confirm. Award click: `computeStudyAward` → `updateCharacter` with
  `{ gcsData: { ...gcsData, skills: updatedSkills, skillHistory: [...(skillHistory ?? []), historyEntry] } }`
  → `awardStudyPoint(projectId)` → `addLogEntry(studyLog.pointAwarded(...))`.
- **Header GM control**: small inline editor for `hoursPerPoint`
  (`data-testid="hours-per-point-input"`, dispatches `setStudyConfig`).
- **"Complete all pending study" button** (`data-testid="complete-all-button"`)
  when >1 pending study task in the current slot.
- Task create: on submit, find-or-create the matching StudyProject
  (`upsertStudyProject`) for (leaderId, skillName, specialization) and stamp its
  id into `StudyData.projectId`; log nothing at creation beyond the usual
  validation path (sessions are logged at completion).
- **Complete** (per card or bulk): `beginResolve` → hours =
  `computeStudyHours(helperIds.length > 0, goodMaterials)` →
  `creditStudyHours(projectId, hours)` → `resolve(taskId, { success: true,
  message: "Studied <skill> <hours>h (<total>/<threshold>h)" })` →
  `addLogEntry(studyLog.sessionLogged(...))` with meta
  `{ characterIds: [leaderId], taskId, quantity: hours }`.

### `StudyTaskForm.tsx`
- Leader select (available characters).
- Skill picker: dropdown of the leader's existing `gcsData.skills` ("Name
  (Spec) — 12, A") **plus a "New skill…" option** revealing name text input +
  difficulty select (E/A/H/VH, default A) + attribute select (ST/DX/IQ/HT/
  Will/Per, default IQ). Existing pick prefills attribute/difficulty
  (difficulty fallback 'A').
- Teacher select (optional): available characters excluding the leader, each
  validated with `isEligibleTeacher` — ineligible characters listed disabled
  with "(can't teach — level too low)". Selected teacher submits as
  `helperIds: [teacherId]`.
- "Good study materials" checkbox.
- Rate preview line: "4h/slot (taught)" / "4h/slot (good materials)" /
  "2h/slot (self-study)".
- No batch mode. Validate via `validateTaskCreation` like the rest form.

### `StudyTaskCard.tsx`
Skill name + leader (+teacher name/level tag when present), materials tag,
hours this slot, status badge; pending → **Complete**
(`data-testid="complete-button"`) and Cancel; resolved → results message.

Export all from `views/index.ts`.
