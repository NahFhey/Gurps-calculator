# SPEC: 13c — Trading/Commerce downtime activity

**Date:** 2026-08-28
**Design source:** `docs/TRADING_COMMERCE_13C_PLAN.md` (decisions are final; do not
re-litigate). Read it first — this spec is the implementation contract for it.

## Background (why)

The party's gather→craft→cook loop produces goods with no way to sell them, and
money (per-inventory `currency: Record<string, number>` maps) has no spend path,
no canonical denomination, and nothing sellable has a price. This lane adds a
`'trading'` downtime activity: one task = one market trip, resolved through a
transaction console (sell/buy/adjust lines, optional whole-basket haggle
contest, atomic Apply), backed by a campaign currency config and a learning
price book.

Codebase rules (non-negotiable):
- Strict TypeScript, `npx tsc --noEmit` clean. **No `as any` anywhere including
  tests. No `@ts-ignore`/`@ts-expect-error`.**
- Redux-style state with Immer. Campaign store: `useCampaignStore()` from
  `src/state/campaignStore.tsx`. Downtime context: `useDowntimeContext()` from
  `src/components/downtime/DowntimeContext.tsx`.
- Business logic in `src/utils/trading.ts` and reducers/selectors, not components.
- `import type` for type-only imports. Dark-Tailwind styling + `data-testid`
  matching the existing downtime views.
- **Model the whole lane on the Rest lane shipped 2026-08-28** — read
  `src/components/downtime/views/RestActivity.tsx`, `RestResolutionPanel.tsx`,
  `RestTaskCard.tsx`, and `src/utils/recovery.ts` before writing code. Trading
  follows the same parent-owns-dispatches pattern.

## Deliverable 3: haggle + pricing engine — `src/utils/trading.ts` (pure)

Use `rollVsTarget('3d6', target)` from `src/utils/dice.ts` (its `margin` is
positive on success). Check dice.ts and the foraging/mining panels for existing
critical-success/failure helpers and reuse them; if none are importable,
implement GURPS crit detection locally (crit success: total 3–4, 5 at skill ≥15,
6 at skill ≥16; crit failure: 18 always, 17 at skill ≤15, or failure margin ≥10).

```ts
export interface HaggleResult {
  leaderRoll: RollVsTargetResult;
  opponentRoll: RollVsTargetResult;
  leaderCritSuccess: boolean;
  dealBroken: boolean;       // leader critical failure — no deal this trip
  shiftPct: number;          // favorable-to-party %, clamp(5 * (leaderRoll.margin - opponentRoll.margin), -30, 30); +30 on leaderCritSuccess; 0 when dealBroken
}
export function resolveHaggle(leaderSkill: number, opposingSkill: number): HaggleResult;

/** Merchant skill: keys 'merchant'/'Merchant' via getCharacterSkills; when absent/0,
 *  default IQ−5 (IQ from gcsData.attributes.IQ, else 10). */
export function getMerchantSkill(character: CharacterLike): { level: number; isDefault: boolean };

export interface TradeLine {
  id: string;
  kind: 'sell' | 'buy' | 'adjust';
  itemKind?: 'material' | 'food' | 'item';   // absent for 'adjust'
  name: string;                              // for 'adjust': the note/reason
  quantity: number;                          // 1 for 'adjust'
  unitPrice: number;                         // pre-haggle; for 'adjust' may be negative (debit) or positive (credit)
  itemId?: string;                           // ItemInstance id for itemKind 'item' sells
  owner?: InventoryOwner;                    // source inventory for item sells
  materialType?: string;                     // Material.type for material sells
}

/** Haggle applies to sell/buy lines only: sell total = round(qty*unitPrice*(1+shift/100)),
 *  buy total = round(qty*unitPrice*(1-shift/100)), both clamped >= 0. Adjust lines pass through. */
export function computeLineTotal(line: TradeLine, shiftPct: number): number;
export function computeTradeTotals(lines: TradeLine[], shiftPct: number):
  { proceeds: number; costs: number; adjustNet: number; net: number };
```

## Deliverable 5: UI

New files in `src/components/downtime/views/` (export from its `index.ts`):

### `TradingActivity.tsx`
Mirrors `RestActivity.tssx` structure: header ("Trading"), "New Trip" button →
`TradingTaskForm`, pending/completed `TradingTaskCard` lists for current
day+slot, resolution panel swap-in, parent owns all store dispatches
(`handleFinalize`). Log `tradingLog.tripCreated` on creation.

### `TradingTaskForm.tsx`
Leader select (available characters, show each option's Merchant level via
`getMerchantSkill` — e.g. "Rina (Merchant-13)" / "Soren (default IQ−5 = 5)"),
merchant/market name text input **pre-filled with `currentLocationName` from
`useOptionalDowntimeContext()`** (fallback empty), opposing skill number input
(default 12). No batch mode. Validates via `validateTaskCreation` like the rest
form.

### `TradingTaskCard.tsx`
Merchant name, leader (+Merchant level tag), opposing skill, status badge;
pending → Resolve/Cancel buttons (`data-testid="resolve-button"`); resolved →
`task.results.message`.

### `TradingResolutionPanel.tsx` — the transaction console
Props: task, leader, `onFinalize(results: TaskResults, outcome)` / `onCancel`;
internal state only (parent dispatches). Sections:
- **Party funds header**: primary-currency balance of the party inventory
  (currency name from config).
- **Sell lines**: add-line picker over (a) party inventory materials and food
  (name/type/available qty — source from the party `Inventory` record's
  `materials`/`food`), (b) equipment/other `ItemInstance`s across ALL
  inventories, owner-labeled ("Soren's Pack"). Quantity (clamped to available)
  + unit price, pre-filled from the price book
  (`makePriceBookKey`) else `ItemInstance.value` else 0, always editable.
- **Buy lines**: freeform — kind (material/food/item), name, type (for
  material), quantity, unit price (book-prefilled by name+kind when known).
- **Adjust lines**: note + signed amount (positive = party receives).
- **Haggle section (optional)**: shows leader's Merchant level vs opposing
  skill; "Roll Haggle" button (`data-testid="roll-haggle-button"`) → one
  `resolveHaggle` call, displays both rolls + shift %, disabled after rolling.
  `dealBroken` → console locks with "The merchant refuses to deal." and Apply
  resolves the task with a no-deal message (no inventory/currency changes).
- **Totals footer**: proceeds / costs / adjustments / net (post-haggle), and the
  resulting party balance. **Apply disabled** (`data-testid="apply-trade-button"`)
  when `balance + net < 0` with an "insufficient funds" notice, or when there
  are zero lines.

### Apply pipeline (in `TradingActivity.handleFinalize`)
1. Sells: material lines → `consumeMaterials('party', [{ name, type, quantity }])`,
   food lines → `consumeFoods('party', ...)`, item lines →
   `consumeItem(itemId, quantity)`.
2. Buys: `acquireItem(item, 'party', 'trade')` — material/food/equipment shapes
   per `AcquiredItem`; equipment gets `value: unitPrice`.
3. Currency: compute `net` (post-haggle). `net > 0` →
   `acquireItem({ kind: 'currency', currencyKey: primary, amount: net }, 'party', 'trade')`;
   `net < 0` → `spendCurrency('party', primary, -net)`.
4. Price book: upsert every sell/buy line's **pre-haggle** unit price via
   `setPriceBookEntry` (the book learns base prices; haggle is per-trip).
5. `resolve(taskId, results)` — message summarizing lines, haggle rolls, net;
   `inventoryChanges` deltas for sold (negative) and bought (positive) goods.
6. `addLogEntry(tradingLog.tripResolved(...))`, meta
   `{ characterIds: [leaderId], taskId, quantity: net }`.
